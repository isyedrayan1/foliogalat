# Galat Family - Tone Quick Reference

**Use this when writing new copy, blog posts, or updating the site.**

---

## ✓ DO THIS

```
Short sentences
Active verbs
Specific words
Real language
Direct
Honest
Human
```

**Examples:**
- "We build products that work."
- "Clean code. Good docs."
- "We ship every month."
- "Systems that don't break."
- "Less chasing. More depth."

---

## ✗ DON'T DO THIS

```
ALL_CAPS_LABELS
[01] Numbering
Corporate buzzwords
Corporate phrases
Explain-y text
Generic statements
Jargon
"Reliable systems"
"Practical outcomes"
"Long-term identity"
"Clarity and durability"
```

**Examples of what NOT to write:**
- "A small tech team that builds products, shares knowledge..."
- "Reliable systems and practical outcomes"
- "Clarity, durability, and practical outcomes"
- "Release cadence is steady"
- "Systems that are easy to operate"

## Meta Descriptions (150-160 chars)

### Formula
`[What we do]. [How we do it]. [Why it matters or what it means]`

### Examples

**Homepage:**
✓ "We build software and share what we learn. Monthly releases, clean code, and long-term projects."

**Blog:**
✓ "Build logs from shipping. Notes on decisions. Essays on what works and what doesn't."

**Products:**
✓ "What we've shipped. Products we build and maintain. Updated monthly."

**Team:**
✓ "Two developers who build together. Full-stack and product engineering expertise."

## Blog Post Openings

**Good opening:**
```
We ship every month. Here's exactly how we scope, 
build, test, and launch. This is from our latest release.
```

**Bad opening:**
```
Our organization's approach to software delivery 
is rooted in a commitment to continuous improvement and 
systematic process refinement across the entire team structure.
```

## Common Phrases to Use

**Instead of flowery corporate language:**
- "doesn't break" (not "reliable")
- "clean code" (not "maintainable")
- "good docs" (not "well-documented")
- "we ship monthly" (not "consistent release cadence")
- "less chasing" (not "focused strategy")
- "more depth" (not "increased engagement")
- "the name sticks" (not "long-term identity")
- "we're sticking around" (not "sustained commitment")

## Writing Checklist

For ANY new copy:

- [ ] Is it under 20 words? (If not, break it into multiple sentences)
- [ ] Does it have an active verb? ("we build" not "our focus is on")
- [ ] Is it specific? ("clean code" not "quality systems")
- [ ] Would a 12-year-old understand it? (If not, simplify)
- [ ] Does it avoid buzzwords? (No "synergy", "leverage", "paradigm")
- [ ] Does it sound like a person wrote it? (Read it out loud)
- [ ] Is it honest? (No exaggeration or fluff)

## Internal Linking

When writing blog posts:
- Link 3-5 times per 1000 words
- Link to related blog posts
- Link to relevant products
- Link to team members' profiles
- Use descriptive anchor text ("see our work" not "click here")

## When in Doubt

Ask yourself:
1. **Would I say this to a friend?** (If not, simplify)
2. **Am I using 3+ fancy words?** (Replace with real words)
3. **Can I say it in half the words?** (Remove fluff)
4. **Does it sound like a person wrote it?** (Read it aloud)

If you answer "no" to any of these, rewrite it.
